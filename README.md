# Руководство, которого у тебя никогда не было

Статический сайт с руководством на 13 глав, интерактивным глоссарием, подсказками-источниками и тремя встроенными инструментами (калькулятор калорий, демо-график «шум против тренда», живой трекер веса). Без базы данных, авторизации и сервера: всё, что вводит читатель, хранится в localStorage его браузера.

Стек: Next.js 15 (App Router, `output: 'export'`), TypeScript, Tailwind CSS 4, MDX. Шрифты Golos Text и JetBrains Mono подключены локально через `@fontsource`, внешних запросов нет.

## Установка и запуск

```bash
npm install
npm run dev      # http://localhost:3000
```

Продакшен-сборка:

```bash
npm run build    # статический сайт в папке out/
```

Хостинг — любой статический (Vercel, Netlify, GitHub Pages), переменные окружения не нужны. Перед деплоем на свой домен поменяй `SITE_URL` в `lib/site.ts` — от него считаются canonical, Open Graph, `sitemap.xml` и `robots.txt`.

## Структура

```
app/                  / (лендинг), /guide, /guide/[slug], /glossary,
                      /blog, /blog/topic/[category], /blog/[slug]
content/chapters/     13 глав в MDX — текст совпадает с исходником
content/blog/         391 статья в MDX
content/blog-index.json  генерируемый индекс статей (см. ниже)
components/           читалка, Proof, Term, три виджета, иллюстрация Слона, блог
lib/                  chapters.ts, blog.ts, glossary.ts, proofs.ts, site.ts
scripts/              сборка индекса статей и разовая чистка
docs/                 отбор статей и разбор противоречий
public/elephant/      иллюстрации Слона
```

## Статьи

391 статья лежит в `content/blog/`. Категории, привязка к главам и отбор для
публикации хранятся не в самих файлах, а в генерируемом индексе — так исходные
тексты остаются нетронутыми.

После добавления или правки статьи пересобери индекс:

```bash
node scripts/build-blog-index.mjs
```

**Отбор.** У каждой статьи есть статус: `core` (связана с конкретной главой),
`adjacent` (та же область, но без главы) или `offtopic` (за рамками темы сайта —
файл остаётся, страница не создаётся). Полный разбор с полными списками —
в `docs/otbor-statei.md`. Чтобы переопределить решение по конкретной статье,
впиши её slug в `MANUAL_STATUS` в `scripts/build-blog-index.mjs`.

**Связка с руководством.** Работает в обе стороны: в конце статьи со статусом
`core` стоит ссылка на профильную главу, а в конце главы — блок «Глубже по теме»
со статьями. Обе стороны считаются из индекса, руками ничего прописывать не надо.

**Статьи на одну тему.** Там, где два текста про одно и то же, обе страницы
остаются, но `rel=canonical` ведёт на основную — в поиске они не конкурируют.
Выбор основной автоматический (по объёму), исключения — в `CANONICAL_OVERRIDES`.

**Противоречия.** Сверка статей с текстом глав дала семь расхождений, включая два
внутри самого корпуса. Разбор и предлагаемые правки — в `docs/protivorechiya.md`.
Ни одна правка не внесена.

- **Подсказки-источники**: данные в `lib/proofs.ts`, в тексте фраза оборачивается в `<Proof id="...">…</Proof>`. Чтобы добавить источник — допиши объект в массив и оберни фразу в нужной главе.
- **Глоссарий**: данные в `lib/glossary.ts` (из раздела «Карта терминов» исходного текста), в тексте — `<Term id="...">…</Term>`, страница со всеми терминами — `/glossary`.

## Как добавить иллюстрацию Всадника

Когда картинка появится:

1. Положи файл в `public/elephant/`, например `rider.png`.
2. Открой `components/ElephantIllustration.tsx` и раскомментируй (или допиши) строку в массиве `illustrations`:

```ts
{ src: '/elephant/rider.png', caption: 'Всадник', alt: 'описательный alt-текст' },
```

Сетка карточек подхватит третью иллюстрацию автоматически, ничего больше менять не нужно.

## Если позже понадобится сервер

Сейчас в проекте сервера нет сознательно: сборка полностью статическая, данные читателя не покидают его браузер. Если решишь добавить серверную часть (например, сбор почты на новые материалы):

1. Убери `output: 'export'` из `next.config.mjs` — появятся серверные возможности Next.js (Route Handlers, Server Actions). На Vercel/Netlify это продолжит работать, но уже не как «чистая статика».
2. Эндпоинт делай как `app/api/subscribe/route.ts` и вызывай его из клиентского компонента формы.
3. Для хранения адресов подойдёт внешний сервис (Buttondown, Mailerlite, Supabase) — тогда своя база всё ещё не нужна, достаточно ключа API в переменных окружения (`.env.local`, на хостинге — в настройках проекта).
4. Данные трекера веса и калькулятора при этом трогать не обязательно: они спроектированы автономными и могут остаться в localStorage. Если захочешь синхронизацию между устройствами — добавь экспорт/импорт JSON, прежде чем тащить их на сервер.

## Что сознательно не так, как в трекерах привычек

В трекере веса нет серий («стриков»), очков, достижений, а пропущенный день не подсвечивается красным. Это не упущение, а прямое следствие текста руководства (глава про ЕЕП): счёт обнуляется каждую полночь, и вина за пропуск не накапливается.
